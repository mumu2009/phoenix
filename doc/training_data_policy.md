# 训练集治理（v3.0）

## 1. 目标

在保持 GNN+Transformer 组合方式不变的前提下，建立可追踪、可复现、可扩展的混合训练集策略。

## 2. 数据来源分层

- 仓内小样本（回归层）
  - 用途：功能验证、接口回归、冒烟训练。
  - 推荐来源：`tests/`、`robots/` 中的可审计文本。
- 外部大样本（训练层）
  - 用途：规模训练与泛化能力提升。
  - 规则：仓库只保留索引文件、版本号、哈希与拉取说明，不直接提交大体积原始数据。

## 3. 数据清洗最小规则

- 字符编码统一为 UTF-8。
- 过滤非法字符、损坏行、空样本。
- 保留样本来源标识（source/version/split）。
- 清洗后必须输出统计摘要：样本数、平均长度、异常条目数。

## 4. 训练样本契约

建议统一为：

```json
{
  "input": "...",
  "target": "...",
  "graph": ["seedA", "seedB"]
}
```

- `input`：模型输入文本。
- `target`：监督目标。
- `graph`：可选图增强线索（节点或关键词）。

## 5. 版本管理

- 每次训练必须记录：数据版本、清洗规则版本、模型参数版本、构建哈希。
- 任何线上模型都应可追溯到具体数据版本。
- 外部数据权威索引文件：`doc/external_dataset_index.example.json`（生产中应替换为真实索引）。
- 外部数据必须包含：`source`、`manifest`、`sha256`、`license`、`owner/reviewer`。

## 5.1 权威来源规则

- 仓库中的训练入口以 `tests/` 与 `robots/` 为准（小样本）。
- 外部数据只允许“索引 + 校验”入仓，不允许原始大语料直接入仓。
- 索引文件更新必须附带审批单号（approval ticket）与版本变更说明。
- 线上训练任务必须在日志中记录索引版本与哈希摘要。

## 6. 验证要求

- 至少通过：编译通过 + 核心 API 回归 + 小样本训练验证。
- 与上一个稳定版本比较：回复正确性不下降、错误率不升高。
