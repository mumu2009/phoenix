## 10.1 每回合生成预算有真实墙钟表型（目标一）

**问题**：基因组里新增的可遗传字段 `MissionGenome::tokensPerTick`
（初始 256，夹在 [32, 1024]，对数空间高斯变异，σ = 变异速率）是否改变一次

**装置**：真模型，不是合成噪声。`tinyllama-1.1b-chat-v1.0.Q4_K_M` 在
`127.0.0.1:8100`（CPU，8 线程，一次加载；这是这台机器上实测最快的本地生成器，
2026-10-26 实测 64 token / 4.4 s）。任务是一个固定提示词的续写：提示词含一段
约 800 token 的固定工作说明（每个回合都要重新 prefill，和现场 worker 每回合
携带 goal/tools/outline 的做法同型），`cache_prompt=false`，`ignore_eos=true`
（预算决定本回合生成的 token 数，超出的内容照样记账）。目标是把一份 1200 个
信息字符的说明写出来。一回合 = 一次 `/completion` 请求，`n_predict` 取
`phoenix::mission::missionTickBudget(genome.tokensPerTick, 512, false, 384)`，
与现场 111 的 worker 调用同一个函数。温度 0。回合之间把已写文本的尾部接回提示
词。达到 1200 个信息字符（`deliverableInformationChars`）即停并记墙钟；32 回合
仍未达到的这一次作废，不进入统计。

**切线**：

1. 每个基因组在一次测量里跑 k=1 次（温度 0、固定提示词、固定预算下生成是确定

   两次之差作为噪声量级记录，不改判据。

## 10.2 连续复制子方程接上离散映射（目标二）

**问题**：局部的离散映射 p'_i = p_i f_i / Σ_j p_j f_j 与连续的 Nowak 方程
dp_i/dt = p_i (f_i − f̄) 是不是同一个东西；现场召回用离散映射排序是否有理论依据。

**装置**：`replica_trace.hpp` 的 `replicatorVelocity`、`replicatorFlow`，探针
`build/tmp/replicator_flow_probe.cpp`，不调用模型。

**切线**（跑之前写定）：

1. 解式 p_i(t) = p_i(0) e^{f_i t} / Σ_j p_j(0) e^{f_j t} 与四阶 Runge–Kutta
   在 200 组随机 (p, f)（2 到 6 个变体，t ∈ {0.25, 1, 2}）上的差 ≤ 1e-6。
2. `replicatorFlow(p, f, 1)` 与 `replicatorStep(p, f)` 的差 ≤ 1e-12。
3. 比值不变：p_i(t)/p_j(t) = (p_i(0)/p_j(0)) (f_i/f_j)^t，相对误差 ≤ 1e-9。
4. 支撑不变：p_i(0)=0 的变体在任意 t 仍为 0。
5. 平均适应度不降：把 [0,2] 切成 2000 步，每步 f̄ 的变化 ≥ −1e-12；且
   t→10 时频率收敛到最大适应度的顶点（≤1e-9）。
6. 现场：`saveAliases` 里用 t=1 的 flow 份额排序，必须与 fecundity×longevity
   的排序逐位一致（离散映射就是单位时间流），日志写 `[flow]`。这不改召回，
   只是把连续方程接到同一批数上。

**失败处理**：数值不过就是实现错，改实现；若第 2 条不成立，说明公式写错，
先停下改文档，不把错的公式留在代码里。

## 10.3 频率序列上的力识别（目标二）

**问题**：一次种群快照不能区分内容偏差和从众偏差；三步以上的频率序列能不能。

**装置**：`replica_trace.hpp` 的 `identifyForce`、`populationFrequencySeries`，
探针 `build/tmp/force_identify_probe.cpp`。三张映射用同一批数：

```
content:    p' = p + B p (1-p)
conformity: p' = p + D p (1-p) (2p-1)
replicator: p' = p f / (p f + 1 - p)
```

每张映射先用第一步反解参数，再把它一路迭代到其余每个观测点，取最大绝对
残差；残差 ≤ 0.01 且亚军至少差 1e-6 才贴标签，否则 undetermined。
常数序列记为 fixed。步数 ≥3 就用全部点；点数越多，混合序列越难冒充。

**切线**：

1. 少于三步 → undetermined；两步的标准快照（2026-10-24 的两份草稿）→
   undetermined。
2. 单步不可识别：p0=0.7、D=−0.8、B=D(2p0−1) 时，第一步两条映射的差 <1e-12。
3. 每张映射随机抽 1000 组（p0∈[0.05,0.95]，B∈[−2,2]，D∈(−2,1)，
   w∈[0.2,5]），三步序列的识别准确率每张 ≥0.95。参数把频率推到 (0,1)
   之外的组不是频率，重抽到三步都在 (0,1) 内再计入；这不放宽分布，只是
   把定义域外的抽样丢掉。
4. 混合序列（第一步内容、后两步从众，参数随机抽）用四个点，被贴上单一力
   标签的比例 ≤0.05；三点前缀的比例另记，不作通过条件。其余如实记
   undetermined。
5. 常数序列 → fixed，不贴内容或从众。
6. 现场：111 的审议日志把硬写的 `force=unidentified` 换成算出的
   `force=<label>`，并把残差写进 `runtime_store/replica_trace/account.json`。
   少于三步时仍然输出 undetermined，不猜。

**失败处理**：准确率不到 0.95 先查是不是实现与公式不一致；若公式本身不能
分开，就记录“不可识别”的结论并改用更长序列（≥4 步最小二乘），用新种子，
不改 0.01 / 1e-6 这两条。
