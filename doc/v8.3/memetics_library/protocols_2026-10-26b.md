## 10.8 背景类修复开放列 MLP 的一类零梯度

**问题**：`theory.md` 引理 10.3 指出，只有一个类别时 softmax 恒为 1，交叉熵
梯度为 0，第一列打不开。上一轮用 Hebbian 外积绕过了它；这一轮换一种利用方式：
在输出层加一个固定的**背景类（null）**，文件类从 1 开始编号。每一步的
交叉熵在 `C+1` 个类上做，即使只有一个文件，目标概率也小于 1，梯度不为 0。
背景类没有正样本，只作为每一步的非目标类被压低。

**装置**：`open_column_router.hpp` 增加 `enableBackground()` 和
`addFileCe()`：`addFileCe` 开一列并调用 `OpenColumnMlp::step(x, cls, lr)`
（U 和 W 都按头文件的一步更新），每文件恰好一步，不跑轮数。`route` 取严格
最大，且要求索引 ≥1、`best - logit[0] > 1e-6`；背景类赢或平局都返回空。
探针 `build/tmp/open_column_ce_probe.cpp`。

**切线**：

1. 加入第一个文件后，它的输出列不全为 0（`|W[1]| > 0`），并且自己的词袋
   路由到它（1/1）。这一条直接检查引理 10.3 被修掉。
2. 三个见过的文件各自路由到自己 3/3；再加第四个文件（新列），它自己的
   词袋路由到第 4 列，旧三个不变（4/4）。
3. 没有任何已知词的词袋 → 空（背景或平局）。
4. 两个完全相同的词袋 → 空。CE 的 softmax 会按类别数缩放每列的步长，所以
   两列分数不一定严格相等；路由器按**结构**判定：查询的已知词集合恰好等于
   两个或更多文件的训练词袋时，不猜，直接空。这是对“证据相同”的实现，
   不是放宽切线。
5. 只含一个新文件特异词的描述 → 路由到它（1/1），背景不抢。
6. 每文件只有一次 `step`，没有第二个 epoch；没有新增别的参数。
7. 与 Hebbian 路由在同一组文件上对比：Hebbian 的 1–5 仍须成立；记录两者的
   新文件 margin。若 CE 在 2 上失败（旧列被后续 step 侵蚀），CE 不接现场，
   Hebbian 继续作为主路由。

**失败处理**：1–5 任一条不过，CE 只留在探针与文档，不接现场；不改切线。

**结果（2026-10-26 19:0x）**：PASS。第一条直接过了引理 10.3（第一列行质量
>0，自路由 1/1）；4/4；unseen 空；相同词袋按结构判空；单词 `identity` 路由到
self（margin 0.8，Hebbian 同例 margin 1.0）；旧列没有被侵蚀。现场接 CE 为主、
Hebbian 为备。

## 10.9 老师命中的稳定性审计

**问题**：两次命中的门能排除“同一句重复”，但不能排除“老师两次都错”。本地
没有真值，不能直接验证对错；但可以验证**稳定性**：同一个描述、同一组档案词，
换一个等价的档案词顺序，老师是否还指同一个文件。若两次顺序给出不同的路径，
这次命中就不稳定，不发布。

**装置**：`cond_profile.hpp` 的 `condProfilePath` 增加审计模式：同一描述分别
用（a）原档案词顺序、（b）档案词逆序 各问一次；两次都非空且路径相同才返回
该路径，否则返回空。审计结果写日志 `[cond-hit] stable=1/0`。探针
`build/tmp/cond_stability_probe.cpp` 用 `condExchangeHook` 注入假老师。

**切线**：

1. 假老师对两种顺序返回同一路径 → 接受，发布规则不变。
2. 两种顺序返回不同路径 → 拒绝，`confirmCondWords` 不发布。
3. 一种顺序返回空 → 拒绝。
4. 接受后的路径进缓存；同一 `(描述, 档案词)` 再问不再发起模型交换。
5. 审计只作用于两次命中门里的“老师命中”，不改 T、不改两次命中的窗口、
   不改词法优先顺序。
6. 真实现场（8107 常驻）用已知日历释义对做一次：记录 stable=1 或 0 的实际
   值，不按结果改切线。

**失败处理**：1–4 不过就修实现；5 被破坏就回退审计。稳定性不是正确性，
`theory.md` 命题 11.3 的边界仍保留。

**结果（2026-10-26 19:0x）**：PASS。两种顺序不一致 → 拒绝（2 次交换）；一种
空 → 拒绝；一致 → 接受 `emotion`（2 次交换）；再问同一个接受对 → 0 次交换
（缓存）。现场 111 的 `[cond-hit]` 增加 `stable=0/1`。

## 10.10 现场同任务墙钟：256 与 411 的 A/B

**问题**：10.1b 在探针里证明了 (1+λ) 选出的 411 token 比 384 快；但那是
探针，不是网关的 mission worker。这次在**正在跑的网关**里做同任务 A/B：

- 装置：`phoenix_main.exe`（含本轮改动）在 5090，基座 8B 在 8082，
  `mission.temperature` 用配置值 0.35；同一 goal；
  `/api/mission/assign` 带 `genome={learningRate:0.05, tokensPerTick:256}` 或
  `411.3`；两个任务用不同 id、同一个 goal。
- 判据：从 assign 返回到 `deliverableInformationChars(deliverable) ≥ 1200`
  的墙钟，轮询 2 秒。A/B 各跑两次，交替（A B B A）。每次达到 1200 立即
  `/api/mission/report {goalAchieved:true}` 停掉。
- 切线：
  1. 四次都必须在 ≤4 回合内达到 1200 字符；否则作废重跑一次。
  2. B（411）的中位**回合数** < A（256）的中位回合数。
  3. B 的中位墙钟 < A 的中位墙钟。
  4. 若 2 成立而 3 不成立，如实记录“回合数下降但墙钟没有”，不声称墙钟胜利；
     下一问换连续代价机制，用新种子。
- 说明：现场温度 0.35，内容不完全确定；回合数是机制的直接量，墙钟是目标量。
  这条不重跑 10.1b，也不改它的切线。

**失败处理**：见 4；另外若 8B 在 5090 的网关里无法生成（回退失败），先修
回退，再重跑，不把基础设施故障记成研究失败。

**结果（2026-10-26 20:0x–20:25，A B B A）**：**FAIL**。

| run | tokens | ticks | ms | info chars |
| --- | --- | --- | --- | --- |
| ab-a3 | 256 | 2 | 209122 | 1547 |
| ab-b1 | 411.3 | 1 | 150750 | 1585 |
| ab-b2 | 411.3 | 3 | 466371 | 1799 |
| ab-a4 | 256 | 2 | 209119 | 1943 |

A 的两次完全一样（2 回合、209.1 s）；B 一次 1 回合 150.8 s、一次 3 回合
466.4 s。中位（两次均值）A 是 2 回合/209.1 s，B 是 2 回合/308.6 s，所以
“B 回合更少”和“B 墙钟更短”两条都不成立。原因是现场的回复形态在变：模型有时
写 `{"action":"write"}` 文件动作、有时写普通文本、有时写计划；每回合追加的
字符数不由预算单独决定。预算仍然进了 `num_predict`（`tokBudget=256/411`），
但它不是现场墙钟的唯一自变量。10.1b 的受控探针结果保留；这条现场 A/B 不重跑，
下一问（10.10b，未跑）要把回复形态也钉住（温度 0 + 纯文本续写），让预算成为
唯一变量。

### 10.10b 温度 0 钉住回复形态（10.10 之后的新机制）

**改动**：把 `config/phoenix.json` 的 `mission.temperature` 临时设为 0（跑完
恢复 0.35），重启网关；目标与 A/B 切线与 10.10 完全相同（1200 字符、256 vs
411.3、A B B A、各两次、B 回合更少且墙钟更短）。温度 0 时同一提示词的回复
形态确定，预算成为每回合长度的主要自变量。

**切线**：同 10.10 的 1–4；不因为 10.10 失败而改数。

**失败处理**：若 A 在温度 0 下也已经一回合达到 1200，则记录“现场这条任务的
最优预算 ≤256”，B 只会因为多解码而更慢；不把这条失败说成 10.1b 失败。

**结果（2026-10-26 22:2x–22:4x，A B B A）**：**FAIL**。

| ab-0a | 256 | 3 | 186967 | 1258 | 是 |
| ab-0b | 411.3 | 3 | 379810 | 1903 | 是 |

B 两次都 3 回合，但每次 291–380 s；A 的一次有效是 3 回合 187 s，另一次在
480 s 内只写了 430 字符（模型在增长后的提示词上改写了很短的片段）。B 的中位
335.5 s 远高于 A 的有效值，回合数也没有更低。温度 0 并没有把“每回合追加多少

411 不可直接搬过来。10.1b 的受控结论保留；现场部署保持 256。若要让现场也做
受控的预算演化，下一问（10.10c，未跑）需要一个“每回合只续写、不再选回复形态”
的工作模式。
