# 2026-10-28f：公平的现场 (1+λ)——同模型、空起点、不合并父稿

信号追踪确认 10.15 的 workMs 选择被两个混淆污染：
1) 子盒是 `assist with: 父 goal`，loop 把父代草稿并进子盒，子盒第一拍有
   起跑优势；
2) 父任务 8B、子盒 Granite，workMs 跨模型。
所以 10.19/10.20 的 138.802 在 8B 和 Granite 上都比 210 慢。

**改动**：
- `mission.childFreshTask=true`：子盒用**父 goal**、**空 prior**、自己的空
  工作区；不再把子盒的续写并回父任务（父稿保持独立）。
- `spawnMissionChild` 在未显式给 `model` 时**继承父任务的 scope model**
  （父/子同一模型），避免跨模型 workMs。
- `mission.autoChildDoneChars=1200`：子盒自己的交付物到 1200 即完成。

**装置**：父任务 `model=granite_moe_e0`，plainTextOnly=true，temperature=0，
初代 210.105，λ=3，G=3；父和子都从空工作区开始同一 goal；每代 report 父任务
后按 `workMs` 选。

**切线**：

1. 每代 3/3 子盒由 `[auto-child-done]` 判完成，无人工 `/child/done`。
2. 每代 adopted 子盒的 `workMs` 严格最小（同模型、空起点才可比）。
3. 父任务的交付物不因子盒合并而增长（`childFreshTask` 的副作用检查）。
4. 用 adopted 基因组在 **Granite 空起点**上对初代 210.105 做 A/B（10.22）：
   adopted 的回合/墙钟中位 < 210，或至少 workMs 更小；两条至少一条。

**失败处理**：若仍不收敛，记录每代 genome/workMs/完成字符数；若
`childFreshTask` 被漏用（子盒仍合并父稿），先修接线再跑。
