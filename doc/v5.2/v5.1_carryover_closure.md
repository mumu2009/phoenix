# v5.1 残余任务闭环

## 1. 目标

本文件用于关闭 [doc/v5.2/todos](doc/v5.2/todos) 中第 0 项遗留任务，把 v5.1 尚未系统化的测试、性能评估和 cli-anything 工具接入整理为可执行规范。

## 2. 测试闭环

### 2.1 覆盖率口径

“100% 覆盖率”在 v5.2 中采用分层口径，而不是只看单一语句覆盖率：

1. 接口覆盖率：已公开 HTTP 接口全部至少有 1 条成功路径和 1 条失败路径。
2. 行为覆盖率：上下文、鉴权、语音、视觉、学习、状态查询六类主链路均有端到端验证。
3. 数据覆盖率：测试必须使用真实或可追溯的样本数据，不能只做空包、网关通断或固定假响应测试。
4. 回归覆盖率：新增接口和新增参数必须进入自动化回归清单。

### 2.2 真实数据原则

测试数据必须满足以下要求：

1. 鉴权测试直接读取 [auth/users.json](auth/users.json) 对应的合法用户样本，验证登录、登出、校验、重置链路。
2. 语音测试使用真实 WAV 或 base64 音频，校验识别文本、阶段结果和错误处理，而不是仅检查接口返回 200。
3. 视觉测试使用真实图片路径或 base64 图片，验证目标检测或图像分析输出结构。
4. 聊天与学习测试必须带实际文本、sessionId、feedback、keywords，验证上下文更新和学习结果是否回写。
5. 外部后端测试若依赖上游服务，应记录上游地址、模型名和超时配置，避免把“连接成功”误判为功能通过。

### 2.3 三套评估体系

v5.2 将 /test 下的评估体系拆成三套互补系统：

1. API 回归体系
位置： [test/apis/main.py](test/apis/main.py)
目标：验证公开路由、状态码、JSON 契约、异常恢复与服务自愈。
输入：真实请求体、鉴权令牌、音视频样本、sessionId。
产物：接口清单 [test/apis/api_inventory.json](test/apis/api_inventory.json) 与日志目录 [test/apis/logs](test/apis/logs)

2. 智能效果评估体系
位置： [test/intelligence/README.md](test/intelligence/README.md)
目标：验证回答质量、任务完成度、语义稳定性和转换前后的一致性。
输入：问答集、参考答案、工具调用任务、检索任务、人格切换任务。
产物：用例样例 [test/intelligence/cases.example.json](test/intelligence/cases.example.json)

3. 性能与资源评估体系
位置： [test/prof/main.py](test/prof/main.py)
目标：比较系统 API 与直连模型的延迟、吞吐、稳定性与质量分数。
输入：标准 prompts、并发配置、目标路由、参考答案。
产物：基准输出文本、延迟统计和质量评分。

### 2.4 验收标准

第 0.1 项在 v5.2 中的完成标准如下：

1. API inventory 能自动再生成并用于回归范围确认。
2. API 回归至少覆盖成功、参数缺失、上游失败、超时重试四类路径。
3. intelligence 目录不再为空，且具备用例格式说明。
4. prof 基准可同时输出延迟和质量两个维度。
5. 文档中明确禁止用单纯 post/get 探活替代功能验证。

## 3. cli-anything 工具接入闭环

### 3.1 目标

通过 cli-anything 将 outsides 下可独立运行的工具封装成稳定 CLI，使模型把工具调用视为标准化动作，而不是零散脚本。

### 3.2 接入规范

每个被接入工具必须满足：

1. 有唯一命令名，采用 cli-anything-<tool> 形式。
2. 支持 --json 输出，便于 AI 解析。
3. 输入参数可通过命令行或 JSON 文件传入。
4. 返回结构至少包含 ok、result、error、elapsedMs 四个字段。
5. 明确超时、重试、权限边界和工作目录。
6. 对不可重入工具声明串行或互斥策略。

### 3.3 推荐封装层次

1. 适配层：把原始第三方命令转换成统一参数接口。
2. 协议层：把 stdout/stderr、退出码和结构化 JSON 统一包装。
3. 调度层：提供同步调用、异步调用、超时终止和失败重试策略。
4. 安全层：限制文件系统访问、网络访问和可执行命令范围。

### 3.4 与 v5.2 算法的关系

cli-anything 之所以被称为“数学底座”，不是因为它直接参与梯度计算，而是因为：

1. 它把计算器、协议求解器和外部数值工具转成统一动作空间。
2. 它允许模型在推理中把高成本子问题外包给确定性工具。
3. 它使混沌演算、近似求解和外部分析能力可被调度与复用。

## 4. 结论

第 0 项在 v5.2 中已通过三项落地动作完成：

1. 明确了测试覆盖率口径与真实数据原则。
2. 完成了三套评估体系的职责拆分与目录归位。
3. 给出了 cli-anything 工具化接入的统一规范。
