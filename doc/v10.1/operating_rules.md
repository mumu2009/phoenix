# 项目常驻规矩（用户 2026-11-17 指示，长期有效）

> 这份文件给"未来的我"和所有 sub-agent 看：越界的自主决定要以这里的规则为界。

## 1. 团队与规模（允许豪放）

- sub-agent **递归最高 5 层**，**每层最多 8 个**。
- **一个方向一个 sub-agent**；Lead（我）只负责：对外回复、调度、核对证据、git 提交、最终裁决。
- token 不是瓶颈：当方向足够独立时，**优先并行展开**（大规模搜索/多候选/多实验臂），
  而不是挤在一个 agent 里串行做完。
- **Lead 不创建 git 分支**。分支只由"被改进的 AI/自改框架"创建，形成树、
  按剪枝策略探索（见 `doc/v10.1/branch_batched_selfmod.md`、`selfmod_tree.md`）。

## 2. 思路来源（文献 + 经典实验方法）

- 思路枯竭时按顺序找：**`doc/` 里已有的设计与历史** → **文献（web_search/web_fetch）**
  → **经典科学实验方法**（对照/消融/盲评/固定种子/置信区间/功效分析）。
- 所有"增强/优化"提议必须能回答：**基线是什么、指标是什么、怎么证伪**。
- 允许创新，但创新必须落成**可复现实验**，不接受"听起来更好"。

## 3. 测试与调试器（不可妥协）

- 任何代码改动：**定向 gtest → 宽回归（268 项）→ 长跑**，缺一不可。
- **调试器优先于猜测**：0xC0000374 / 悬垂指针 / 静默退出，先拿到调用栈或断言位置
  再改代码。工具链：`tools/dump_stack_resolve.py`（minidump + linker map）、
  WER LocalDumps、PageHeap/Application Verifier、gdb/cdb（MinGW 版）。
- 已知边界：`-D_GLIBCXX_DEBUG` 与 conan 预编译库 ABI 冲突（实测链接失败），不要重试。
- 不许用 `if(false)`/注释掉业务逻辑/降级为串行 的方式"消除"问题。

## 4. 稳定性（长期可运行版本是首要交付）

- 稳定版本比新功能重要：**先保证 3 小时量级连续可运行**（覆盖至少一个完整任务生命周期），
  再谈下一轮改动。
- 稳定性证据**不要求**"无限长时间"，但要求**中等时长 + 结构化证据**：
  进程 up 率、每 tick 耗时、崩溃/重启次数、dump 数量、GPU/slot 占用、
  任务完成情况（assign→report）。
- 每次改动后按"侧车二进制 + 独立端口 + 独立 soak 窗口"验证，**不打断生产长跑**。
- 崩溃率是硬指标：同签名崩溃 >1 次/3h 视为未修复。

## 5. 交付与留痕

- 我（Lead）统一 git 提交；sub-agent 不 commit、不 push、不建分支、不 reset。
- 每次改动留：根因/diff/编译日志/gtest 汇总/soak 摘要；文档写进 `doc/v10.1/`。
- 对外发布走 `doc/publish/`（文案+审计），Lead 判断是否 push。
