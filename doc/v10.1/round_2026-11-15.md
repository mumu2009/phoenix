# 本轮工作总结 — 2026-11-15（v10.1 → v10.2）

## 0. 起点

- 长跑稳定（CUDA，`-ngl 99`），但 **GPU 利用率 1–8%**，用户要求查明。
- `study.expert.enabled=true` 但运行时 `expert.enabled=false`，`weights.json` 自
  2026-11-13 21:13 冻结。
- 关掉 `autonomyLoop.missionDelibLock` 时 `phoenix_main.exe` 每约 60 s 堆损坏崩溃
  （`0xC0000374`）。

## 1. 根因一：LLM 请求根本没有到达服务器（GPU 空转的真因）

`callLlamaCppBackend()` 在我上一轮加入的"尊重 `llamaUseSplitBackend`"分支里写成：

```cpp
if (!llamaUseSplitBackend) return chatWithLlamaCpp(text, ...);   // ← 递归！
```

而 `chatWithLlamaCpp()` 正是**先取 llama slot、再调用** `callLlamaCppBackend()`
的函数。于是每层递归都多占一个 slot；`maxSlots` 层之后所有调用都返回
`llama-slot-busy`，**没有任何请求真正发给 llama-server**：

- `nvidia-smi`：SM 1%，显存 5.8 GB（权重常驻，与利用率无关）
- `llama-server` 日志：`srv update_slots: all slots are idle`
- 网关日志：`[mission-deliberate] llamacpp FAIL err=llama-slot-busy` 刷屏

由于 `config/research/full_components.json` 把 `llamaUseSplitBackend` 设为
`false`（CUDA 稳定性要求），这条**递归路径就是默认路径**——所以"GPU 空转"
其实是"模型从未被调用"。

### 修复

新增 `phoenix::v7::llamaTextChat()`（`module_overrides/llama_split_backend_client.cpp`）：
用与 split 管线**完全相同的因果提示组装**（`cleanGraphContextForSystem` +
`assembleCausalText` + `resume_suffix`），POST 到**原生 `/completion` 端点**。
这才是"text-only 路径"本来该做的事：不碰 `/phx` 共享 `llama_context`（崩溃源），
但真的把请求送到 GPU。

同时把 mission（lowPriority）的 slot 等待上限 60 s → 15 s：mission tick 本来
就会下一轮重试，没必要在 deliberator 里停一分钟。

## 2. 根因二：并行 mission 的堆损坏（三处未加锁的 lambda 静态）

详见 `doc/v10.1/crash_forensics_2026-11-15.md`。要点：

| 缺陷 | 修复 |
|---|---|
| `explorePaths` 惰性 `push_back`（可重分配）与遍历并发 | 改成不可变魔法静态 `gatewayExplorePaths()` |
| `namedRealPath` 全局 `std::string` 并发写 + 跨任务串味 | 改为按 scope 的 map + 互斥 |
| `sectionDropStreak` 无锁 `std::map` | 封装为 `ScopeCounter`（互斥 + get/set/inc） |
| `TinyExpert::fromJson` 无锁改权重 | 拆 `fromJson`（加锁）/`fromJsonLocked`（调用方持锁） |

修复后粗锁 `missionDelibMu_` 不再是正确性前提，只是性能开关 →
`autonomyLoop.missionDelibLock=false` 可以安全打开。

## 3. 根因三：配置被持久化状态覆盖（expert 永远 disabled）

`importState()` 会把 state 文件里的 `studyExpert.enabled` 恢复到内存，
而该字段是**那次写盘时的旧开关**。于是 `config/phoenix.json` 里后加的
`study.expert.enabled: true` 永远不生效。

修复（`autonomy_stack.cpp`）：

- 新增 `applyStudyConfigPayload()` / `reapplyStudyConfig()`：
  **配置拥有开关与路径，状态只拥有权重与计数**；
- `importState()` 在恢复权重之后回放配置（population 的 `n` 不回放，否则会
  重新播种并丢掉刚恢复的个体）；
- `configureStudy()` 缓存生效载荷，回放时以它覆盖全局配置。

验证：`runtime_store/experts/study_tiny/weights.json` 在 11:04:24 被更新
（自 11-13 起首次），`[field-train] expert=queued` 出现。

## 4. 新增能力

### 4.1 异步训练（隐藏 CPU 耗时）

`noteFieldOpportunity()` 原来**同步**跑 `trainProjectTree(".")`（扫全仓库 + SGD），
整段 CPU 时间把 mission 循环（也就是 GPU 流水）卡住。

现在改为单后台 worker：

- `trainMu_/trainCv_/trainQueue_/trainThread_` + `trainingPending()`；
- 调用方立即返回 `expert=queued`，训练与下一轮 decode 重叠；
- 结果落在 `lastExpertTrain_`，`status().study.expertTraining` 暴露
  `busy/jobsDone/pending/last`；
- 析构时 `stopTrainingWorker()` join，保证不留下悬空线程。

### 4.2 插件意图识别：模因层语义驱动

`addon.cpp::collectOffers` 的老逻辑是"每个插件自己的关键词打分，低于阈值直接丢"，
所以用词不同但语义匹配的插件永远选不上。

`plugin_semantics.hpp`（纯函数，可单测）+ `065` 接线：

- 先把候选阈值降到 `addons.semanticFloor`（默认 0.10）拿到候选；
- 两条语义通道：
  - `lexical`：去停用词的内容 token Jaccard（与词序无关）；
  - `memetic`：候选词与情境词的**模因簇交集**（`kvm_.getWordMemeSet`），
    外加 `consistent/consistency` 这类词形回退；
- 融合：`blendOfferScore = pluginScore * (0.5 + 0.5*semantic)` ——
  语义证据可以放大/衰减插件分，但**不会一票否决**（fail-open）；
- 最后才用 `addons.offerMinScore` 过滤并排序。

### 4.3 专家召唤：评分选择而非"第一行获胜"

`summon_registry.hpp` 新增 `EndpointStats` + `EndpointRanker`：

```
score = roleBonus + reliability*1.5 - 0.5*inFlight
        - 1.5*min(consecutiveFailures,4) + sticky(60s)
```

- `selectForSourceEdit()` 改为按分数挑选（并要求 role 匹配，不再只认 `kind=="moe"`）；
- `noteSummonStart/noteSummonOutcome` 由网关在专家调用前后记账，
  产出真补丁=成功，散文/失败=失败；
- 副作用：连续两次写不出补丁的专家会自动被降权，不再被无限召唤。

### 4.4 符号推理层（Prolog/Datalog 风格）

`logic_engine.hpp`（header-only）：事实 + Horn 子句 + 前向链（不动点）+
后向链（SLD，深度/解数上界）+ 内建比较；`runJson()` 作为工具门面。
注册为 AGI 动作 `logic`（`registerDefaultAgiActions`，动作维度 5→6），
因此 EFE 规划器可以像选 `math`/`search` 一样选它，无需给 base 模型写提示词。
详见 `doc/v10.1/logic_engine.md`。

## 10. 最终结论（2026-11-15 晚，收尾）

### 10.1 第 5 处竞争：由 dump 栈指认并修复

`tools/dump_stack_resolve.py` + `phoenix_main.map`（24 MB，编译时 `-Wl,-Map` 生成）
解析 `phoenix_main.exe.12412.dmp` 得到：

```
addon::invokeAddonOnlineLookup -> RuntimeState::onlineLookup
  -> OnlineResearcher::lookup -> OnlineResearcher::fromCache
```

`OnlineResearcher` 的 `cache_` 完全无锁：`fromCache()` 会 `cache_.erase(it)`，`remember()`
插入并 `pruneCache()` 删元素；8 路 mission 并行时一个线程删、另一个线程遍历 →
`0xC0000374`。修复：新增 `mutable std::mutex cacheMu_`，`fromCache`/`remember`
全程加锁，`pruneCache()` 改为"调用方已持锁"（仅 `remember` 调用，避免自死锁）。

**同一队列中的其他 5 处竞争**（详见 `crash_forensics_2026-11-15.md`）：
`explorePaths` 惰性 realloc、`namedRealPath` 全局 string、`sectionDropStreak` 无锁 map、
`TinyExpert::fromJson`、`executeAgiAction` replicate 分支在锁外写 `sessions_`、
`ScopedTrainableMemory` 同 scope 字符串写。

### 10.2 GNN：不移植 GPU，也不做异步预取（用测量否决）

日志实测 `gnnMs = 1`（6 个样本，最大 3 ms），而一次生成为**秒级**。
因此：
- GPU 移植没有收益（PCIe 传输 + kernel launch 远大于 1 ms）；
- 异步预取同样没有收益（1 ms 藏在几秒后面，误差级别）。
结论：**GNN 不在性能关键路径上**，保持现状。该判定替代了"GNN GPU 化"这一待办，
属于"以数据关闭需求"，不是功能降级。

### 10.5 `process_token` 崩溃（objecive 第 2 项的后半）

`llama-server` 的 `0xC0000005 @ process_token (0x7286e)` 只发生在 `/phx` split 端点
（API 线程在共享 `llama_context` 上解码）。当前部署**不再走该路径**：

```
llamacpp(split)      => 0        （日志中一次都没有）
text_path=completion => 108
llamacpp(text)       => 111
llama-server 今日崩溃事件 => 0
```

即：该崩溃被"换掉执行路径"消除，而不是被修复。split 补丁的重开条件仍记录在
`doc/v8.0/migration_backlog.md` 与 `enc_dec_separation.patch` 头部（temp>0 不再泄漏
模板 token、`GGML_ASSERT` 不再触发）。这是一条**明确的边界**，不是"已修好"。

### 10.6 同类缺陷复查（同一类"未加锁容器"）

- `OnlineResearcher`：`cache_` 未加锁（已修）；`docs_` / `invertedIndex_` /
  `aspectToUrls_` / `urlToContent_` 在 `indexDocument` 与三个查询函数中**都**持有
  `indexMu_`，本次逐行核对确认无遗漏；
- `cross_context_memory.hpp` / `mission_experience.hpp`：均有函数级 `static std::mutex`
  保护，安全。

### 10.7 召回宽度（MMR）

`experienceTop` 只按相关性排序取 top-k，k=3 时三条几乎相同的旧配方可以占满全部槽位——
模型拿到的是同一个思路重复三遍。按用户"竞争性/贪心算法必须保宽度"的要求，新增
`retrieval_diversity.hpp`（MMR，Carbonell & Goldstein 1998）：

```
mmr(i) = λ · rel(i) − (1 − λ) · max_{j∈S} sim(i, j)
```

- `λ = 1` 与旧的贪心顺序**完全一致**（不静默改变行为）；
- `λ` 由 `mission.recallDiversity` 控制（默认 0.7）；
- 相似度用既有的 `experienceOverlap`，无新依赖；
- 测试 `test_retrieval_diversity.cpp` 5 例：λ=1 等价贪心、近重复不再占满、空输入/k=0/k>n
  安全、同分确定性、NaN 相似度被忽略。

至此"宽度"要求在三条选择路径上都有实现：召唤（`pickSoftmax`+退火）、
探索路径（`pickExplorePath`）、召回（`mmrSelect`）。
